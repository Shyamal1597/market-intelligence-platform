# Sunidhi Intranet — Changes Summary (2026-05-14)

## 1. NSE Filings Search — Partial Match Fix

**File:** `lib/nse-aliases.ts`

**Problem:** Searching "mta" in the BSE Filings page returned no results because `expandSearch()` only did exact key lookups in the alias map — it wouldn't find "mtar" or "mtartech".

**Fix:** Rewrote `expandSearch` to do substring matching across all alias keys and values. If the search term appears anywhere within a key or any of its aliases, the entire alias group is included in results. Exact matches still take priority.

## 2. Intel Dashboard — Multiple Bug Fixes

### 2a. Empty "All Quarters" Dropdown Removed

**File:** `components/intel/FiltersBar.tsx`

**Problem:** The quarter filter dropdown always showed "All quarters" with no options because `SegmentCard` passes `quarters={[]}`.

**Fix:** Wrapped the dropdown in a conditional — it only renders when `quarters.length > 0`.

### 2b. Metrics Dropdown Filtered to Relevant Items

**File:** `components/intel/SegmentCard.tsx`

**Problem:** The metric dropdown showed every metric from the sector registry, including many with zero claims.

**Fix:** Built a `Set` of metric keys that actually have claims, then filtered the registry against it. Only metrics with at least one claim appear in the dropdown.

### 2c. Self-Referencing Check Bug

**File:** `app/api/intel/[symbol]/route.ts`

**Problem:** Q4-FY26 forward-looking claims were being "verified" against Q4-FY26's own transcript — the same earnings call where the guidance was given. This produced meaningless verdicts (e.g., "moving") for claims that haven't actually been tested yet.

**Fix:** Added an `isSelfRef` guard in `enrichClaims`: if `check.verifiedInQuarter === sourceQuarter`, the check is nullified. The claim correctly shows as unverified.

### 2d. Misleading Pending/Ambiguous Messages

**File:** `components/intel/ClaimDetail.tsx`

**Problem:** All pending claims showed "Awaiting next quarter's results" even when the claim had no target quarter (forward guidance with `targetQuarter: null`).

**Fix:** Differentiated between two pending states:

- `verifiedInQuarter === "unknown"` or no `resolvedTargetQuarter` → "Forward guidance — no target quarter yet"
- Otherwise → "Awaiting next quarter's results"

Also fixed the right-side header showing raw "unknown" — now displays "Verification pending".

### 2e. Empty Quarter Column Hidden + Latest Guidance Section

**File:** `components/intel/IntelDashboard.tsx`

**Problem:** Q4-FY26 appeared as a column with no summary and no verified claims — just empty space. Users questioned why it was there.

**Fix:**

1. Filtered `sortedQuarters` to only include quarters that have at least one verified claim (met/moving/miss verdict).
2. Created a `LatestGuidanceSection` component that appears below the verified quarters grid. It shows forward-looking claims from unverified quarters with a clear explanation: these are promises from the most recent earnings call that can't be verified until the next quarter's transcript is ingested.
3. Each claim in the section shows the metric, direction, quote, and a "pending" badge.

## 3. Derivatives / Option Chain Page — Enhancements

### 3a. Resistance & Support Walls (Peak OI Strikes)

**Files:** `lib/nse-derivatives.ts`, `components/derivatives/ChainSummary.tsx`

**Problem:** The summary bar only showed Max Pain. Users wanted call/put max pain.

**Initial attempt:** Computed separate call/put max pain by minimizing writer loss independently. This produced wrong values (CE gravitated to lowest strike, PE to highest) because minimizing one side's loss in isolation is mathematically trivial.

**Final fix:** Replaced with "Peak OI Strikes" — the strike with highest CE open interest at or above spot (resistance wall) and highest PE open interest at or below spot (support wall). These are the key levels options writers are defending. Labeled as "Resistance" and "Support" in the UI.

Added `peakOIStrikes()` function and `cePeakOI`/`pePeakOI` fields to `DerivativesData`.

### 3b. Total OI & Total Volume Surfaced

**Files:** `lib/nse-derivatives.ts`, `components/derivatives/ChainSummary.tsx`

**Problem:** NSE's API returns `filtered.CE.totOI`, `filtered.PE.totOI`, `filtered.CE.totVol`, `filtered.PE.totVol` but these were never displayed.

**Fix:** Added `totalCeOI`, `totalPeOI`, `totalCeVol`, `totalPeVol` to `DerivativesData`. The summary bar now has a second row showing Total OI (CE/PE split) and Total Vol (CE/PE split) with the `fmtLargeNum` formatter (Cr/L/K notation).

### 3c. Summary Bar Redesigned

**File:** `components/derivatives/ChainSummary.tsx`

Complete rewrite from a single-line layout to a two-row information-dense bar:

- **Row 1:** Spot price, ATM IV, PCR (color-coded: teal >1.2, red <0.8), Max Pain, Resistance/Support walls, Market Open/Closed indicator with pulse animation, last updated timestamp.
- **Row 2:** Total OI (CE cyan / PE red), Total Volume (CE cyan / PE red).

Added `Metric` sub-component for consistent label+value rendering.

### 3d. Volume Column Added to Chain Table

**Files:** `components/derivatives/ColumnToggle.tsx`, `components/derivatives/ChainRow.tsx`, `components/derivatives/OptionChainTable.tsx`

**Problem:** Volume data (`ceVol`/`peVol`) was fetched from NSE but never shown in the table.

**Fix:**

- Added `vol: boolean` to `ColumnConfig` (default: false, toggleable in Columns panel under Market group).
- Added Vol header columns to `OptionChainTable` for both call and put sides.
- Added Vol data cells to `ChainRow` using the same `fmtOI` formatter as OI columns.
- Updated `callExtraCols`/`putExtraCols` colspan calculations to include the vol column.
